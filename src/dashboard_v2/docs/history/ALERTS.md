# 이상진단 알림

## 동작
- /alerts 페이지와 사이드바 알림 배지는 각 샘플의 diagnosis를 사용한다.
- 모터·버스·실행·서버/소스 세션·이상 코드별로 한 번의 발생을 한 건으로 기록한다.
- 같은 이상이 지속되면 마지막 이상 확인 시각만 갱신한다.
- 유효한 다음 판정에서 사라진 코드는 해제한다. 해제 후 재발은 새 알림이다.
- 미수신, null, waiting, 잘못된 판정은 해제 근거가 아니다.
- 요약과 필터는 전체 기록, 발생 중, 해제됨, 미확인, 확인으로 구분한다. 발생 중은 현재 유효한 수신 상태에서 지속 중인 이상이며, 해제됨은 후속 판정에서 해당 이상이 사라진 기록이며, 미확인/확인은 사용자의 알림 확인 여부이다. 해제되어도 자동으로 확인 처리하지 않는다.
- 조회하지 않은 발생 건수가 사이드바 배지에 표시된다. 100건 이상은 99+로 표시하고 접근성 라벨에는 실제 수를 제공한다.
- 알림 행을 클릭하거나 키보드 Enter/Space로 선택하면 해당 알림만 확인 처리한다. 페이지 진입·새 데이터 수신·탭 복귀·검색·필터·페이지 이동으로는 읽음 처리하지 않는다. 미확인 알림은 강조 표시하고 클릭한 건만 배지에서 차감한다.
- 목록은 확인 여부, 발생 시각, 확인 시각을 표시하며 현재 지속 중인 이상에는 발생 중을 별도로 표시한다.
- 읽음과 이상 해제는 별개이다. 읽거나 정상 복귀해도 발생 기록은 삭제하지 않는다.
- 최신 발생순 목록, 이상 종류/모터/ID/버스 검색, 상태 필터, 25건 단위 페이지를 제공한다.

## 백엔드 계약
기존 schemaVersion:1 snapshot/reset/samples 통신은 변경하지 않았다.
샘플은 식별 정보, seq, elapsedMs, timestamp(없으면 receivedAt)와 다음 진단을 포함한다.

정상: {"state":"normal","codes":[]}
이상: {"state":"fault","codes":["overload","friction"]}
대기: {"state":"waiting","codes":[]}

**codes는 해당 모터의 현재 활성 이상 전체 목록이다. 추가된 코드만 보내는 변경분이 아니다.**
동시 발생한 코드는 각각 알림 한 건을 만든다. 알려지지 않은 코드는 원래 코드와 함께 미분류 이상으로 표시한다.
하드웨어 오류, 실험 조건, 그래프 값에서 알고리즘 판정을 추측하지 않는다.

재연결 시 같은 서버/소스/실행 ID와 증가하는 seq를 유지해야 같은 기록으로 이어진다.
저장한 체크포인트 이전의 snapshot 재전송은 중복 알림을 만들지 않는다.
서버/소스/실행 ID가 바뀌면 해당 소스의 알림을 초기화한다. 같은 실행 재연결에서는 기존 알림과 확인 상태를 유지한다.
첫 연결/재연결 snapshot에서는 새 알림을 생성하지 않는다. 순번 체크포인트와 기존 알림의 해제 여부만 갱신한다. running/finishing이며 readerCaughtUp이고 writerActive가 false가 아닌 동안 새 samples 메시지로 수신한 유효한 fault만 알림을 생성한다. 같은 코드 지속은 중복 생성하지 않고 해제 후 재발은 새 알림으로 표시한다.

## 보관 범위
알림과 확인 시각은 페이지 메모리에만 보관한다. 이전 localStorage 키를 읽거나 쓰지 않으므로 기존에 저장된 4건도 복원되지 않는다. 새로고침·새 브라우저 접속은 0건에서 시작한다. 이후 새 이상 판정이 들어오면 해당 알림이 생성될 수 있다.
페이지 내부 이동·동일 실행 재연결에서는 메모리를 유지한다. 실제/가상 소스는 별도로 보관하며 각 소스에서 새 실행 ID를 받으면 이전 기록을 초기화한다. 실험이 종료되더라도 현재 페이지에서 발생했던 알림은 확인할 수 있다. 전체 과거 이상은 상세분석/로그의 상태 이력을 사용한다.
