# 모터 제어 및 실험 기록 관리 계획

상태: 구현 완료. 제어 설정 저장, 수동 시작/왕복 완료 후 종료, 날짜별 기록, 로그 목록과 과거 분석 화면을 구현했다. 실제 모터는 구동하지 않고 모의 장치와 브라우저로 검증했다.

현재 사용법과 API는 [CONTROL.md](CONTROL.md), 기록 조회 계약은 [HISTORY.md](HISTORY.md)를 참고한다. main.py는 대기 상태로 시작한다.

## 1. 확정 사항

- 사이드바 순서: 개요 → 제어 → 모터 → 상세분석 → 알림 → 로그.
- 제어 페이지에서 모터와 왕복 조건을 입력/선택하고 저장하면 백엔드가 검증한 config 파일을 만든다.
- 설정 저장만으로 모터 연결이나 실험을 시작하지 않는다.
- main.py 실행 시 서버와 화면은 대기 상태다. 실험 시작 명령을 받은 후 측정값 생성/수집, 실시간 전송, CSV 저장을 시작한다.
- 종료 버튼은 **현재 진행 중인 왕복 한 주기를 끝내고 종료**한다. 즉시 멈춤이나 일시정지가 아니다.
- 정상 종료, 지정 횟수 완료, 사용자의 종료 예약 처리에서 **토크를 해제하지 않는다**. torque_off_on_normal_exit=false를 고정하고 화면에 토크 해제 선택지를 두지 않는다.
- 실험 종료 후 다시 시작하면 새 runId, 새 파일, 경과 시간 0초로 시작한다. 이전 CSV에 이어 쓰지 않는다.
- 개요의 모터 그림 아래에는 시작/종료 버튼만 둔다. 설정 편집은 제어 페이지에서만 한다.
- 제어/개요는 동일한 백엔드 실험 상태와 시작/종료 API를 사용한다.
- 완료된 실험을 날짜별로 찾고 상세분석과 같은 그래프로 여는 로그 페이지까지 이번 개발 범위에 포함한다. 제어·저장·목록 조회·과거 분석을 한 흐름으로 구현하고 검증한다.
- 화면은 시연용이다. '알고리즘이 판단', 'MOCK 판정 예시' 등 개발자를 위한 설명을 추가하지 않는다. 필요한 상태·모터 식별·단위·오류만 간결하게 표시한다.

## 2. 프로젝트 경계

- src/experiment/ 원본, 원본 설정, 원본 실행 방식은 변경하지 않는다.
- 제어 관리 기능과 실험 연동 변경은 src/dashboard/ 안에 둔다. 기존 dashboard/experiment 복사본의 왕복 순서와 q 종료 예약 방식을 재사용한다.
- 웹 요청을 처리하는 동안 왕복 루프를 직접 실행하지 않는다. 백엔드의 실험 관리자가 별도 실행 작업/프로세스를 소유한다.
- SDK·COM 포트에 접근하는 주체는 하나다. 기존 터미널 실험과 웹에서 시작한 실험이 같은 포트를 동시에 점유하지 못하도록 기존 실행 잠금과 연계한다.
- MOCK과 실제 실험 기록은 서로 다른 저장 루트를 사용한다. 브라우저의 표시 소스를 바꾸는 동작은 실행 중인 실험을 종료하거나 다른 실험을 시작하는 명령이 아니다.

## 3. 설정 저장

현재 ExperimentConfig와 TOML 형식을 재사용한다.

| 묶음 | 설정 |
|---|---|
| 모터 연결 | 모델, ID, COM 포트, 통신 속도 |
| 왕복 동작 | 회전수, 방향, 가속 시간(ms), 전체 이동 시간(ms) |
| 반복 | 상단/하단 대기 시간, 왕복 횟수 |
| 수집 | 수집 주기, 필요 시 CSV 반영 설정 |
| 실험 조건 | 정상/마찰/과부하 등 분류, 해당할 때 부하량 |

- acceleration_ms는 가속도가 아니라 가속 시간이다. 화면 명칭과 단위를 일치시킨다.
- 가속 시간은 이동 시간의 절반 이하, 이동 제한 시간은 이동 시간보다 길어야 한다. 모델·ID·통신 속도 등 기존 검증을 백엔드에서도 적용한다.
- Protocol 2.0 및 토크 유지 정책 등 변경할 필요가 없는 값은 사용자 입력에서 제외한다.
- 초기 구현은 실행 중 또는 종료 대기 중 설정 저장을 막는다. 편집한 값은 먼저 저장해야 실행할 수 있다.
- 저장된 설정에는 식별자/버전을 부여한다. 시작 요청이 그 설정을 지정하고, 백엔드는 이를 해당 실험의 config.toml로 복사한다.
- 실행별 config.toml은 이후 공용 설정 변경의 영향을 받지 않는다.
- 실험 조건 분류와 수신한 이상 판정 결과는 별개다. 조건 이름을 곧바로 판정 결과로 사용하지 않는다.

## 4. 시작과 왕복 완료 후 종료

대기 → 시작 중 → 실행 중 → 종료 대기 → 완료
시작/실행 오류 → 오류 또는 중단

- 버튼 문구는 '실험 시작', '실험 종료'를 기본으로 한다. 종료 요청 후에는 '종료 대기'로 표시하고 반복 요청을 막는다.
- '실험 종료'는 현재 주기의 상승 → 상단 대기 → 복귀 → 하단 대기를 완료한 뒤 다음 주기를 시작하지 않는 종료 예약이다.
- 종료 대기 동안 측정·전송·CSV 기록을 계속한다. 버튼을 누른 순간 CSV를 닫지 않는다.
- 끝나면 마지막 데이터를 반영하고 CSV flush/close, 종료 시각·사유·완료 횟수를 기록한 뒤 완료 상태를 알린다.
- 지정 왕복 횟수 도달도 동일한 종료 정리와 토크 유지 정책을 적용한다.
- 시작 중 아직 왕복이 시작되지 않았다면 종료 예약을 반영해 새 주기를 시작하지 않도록 처리한다.
- 중복 시작은 백엔드에서도 차단한다. 종료 요청에는 runId를 포함해 과거 화면의 늦은 요청이 새 실험을 종료하지 않게 한다.
- 새로고침·페이지 전환·브라우저 연결 종료는 실험 종료 명령이 아니다. 재접속하면 백엔드 상태를 다시 받는다.
- 정상적인 서버 종료 시 실행 작업에도 종료 예약과 정리 절차를 적용한다. 강제 종료나 통신 오류로 왕복이 끝나지 않았다면 완료로 기록하지 않는다.
- 소프트웨어에서 토크 OFF를 보내지 않는 정책이다. 장치 자체의 보호 동작·전원 상실까지 위치 유지를 보장한다는 뜻은 아니다. 상태를 확인할 수 없으면 정상 종료로 표시하지 않는다.

개요의 실행 대상은 저장된 실행 설정의 모터다. 조회용 모터 선택만으로 실행 대상이 변경되지 않는다. 버튼 주변에는 실행 대상과 현재 상태를 짧게 표시한다.

## 5. 날짜별 저장 구조

날짜는 **년 / 월 / 일**로 분리하고, 실험 시작 시각의 한국 시간(Asia/Seoul)을 기준으로 폴더를 결정한다. 자정을 넘어도 하나의 실험은 시작 날짜 폴더에 유지한다. 아래 구조로 저장하며 기존 파일은 자동 이동하지 않는다.

```text
src/dashboard/
  runtime/
    control/
      saved.json
      configurations/
        <설정ID>.toml
    mock_runs/
      YYYY/
        MM/
          DD/
            <HHmmss>_<runId>/
              config.toml
              metadata.json
              telemetry.csv
    experiment_runs/
      YYYY/
        MM/
          DD/
            <HHmmss>_<runId>/
              config.toml
              metadata.json
              telemetry.csv
```

- mock_runs는 가상 실험 전용, experiment_runs는 대시보드 제어로 시작한 실제 실험 전용이다. mock_data_root를 기준으로 같은 부모 아래 experiment_runs와 control을 둔다.
- 기존 원본 실험의 results/raw 및 현재의 날짜 없는 mock_runs 기록은 보존한다. 로그의 기존 기록 지원이 필요하면 별도 읽기 어댑터로 다루며 덮어쓰거나 옮기지 않는다.
- 시간과 고유 runId를 함께 사용해 같은 초의 여러 실험도 구분한다.
- 모든 기록의 기본 키는 runId다. 날짜·모터·실험 조건은 검색용 속성이다.
- 생성된 데이터는 Git에서 제외하고, 자동 삭제는 이번 계획에 포함하지 않는다.

### 파일 역할

- config.toml: 시작 시 확정한 실험 설정 사본. 실제 실행에 사용한 값을 기록한다.
- telemetry.csv: 전체 원본 측정값과 수집 시각/순번, 모터 식별 정보, 수신한 판정 결과. 샘플링/평균 없이 기록한다. 포맷 버전과 해석 방식은 metadata에 명시한다.
- metadata.json: 파일 목록과 실험 요약. JSON은 임시 파일 작성 후 교체해 중간 상태가 읽히지 않게 한다.

metadata에는 다음을 포함한다.

- schemaVersion, telemetrySchemaVersion, runId, source(mock/real).
- 시작·종료 시각(시간대 포함), 날짜 폴더 기준 시간대.
- 상태, 종료 요청 시각, 종료 사유(사용자 종료 예약/횟수 완료/오류/중단).
- 모델, 모터 ID, 실험 조건, 수집 주기, 설정 식별자/버전.
- 설정/CSV의 실행 폴더 기준 상대 경로, 누적 행 수, 마지막 순번, 실제 기록 구간, 완료 왕복 횟수.
- 판정 형식 버전과 공급자가 제공한 경우 알고리즘 버전. 제공되지 않은 버전이나 판정 결과를 만들어 넣지 않는다.

진행 중에는 적절한 간격과 상태 전환 시 요약을 갱신하고, 종료 시 최종화한다. 재시작 후 실행 작업이 없는 과거 running/finishing 기록은 중단 여부를 확인해 분류한다. 파일이 있다는 이유만으로 완료 처리하지 않는다.

## 6. 로그 페이지 — 이번 구현 범위

- 년 → 월 → 일로 범위를 좁히고 해당 날짜의 실험 목록을 표시한다.
- 목록 기본 항목: 시작 시각, 모터/ID, 실험 조건, 실행 시간, 완료 횟수, 종료 상태.
- 완료 기록을 기본으로 제공하되 오류·중단 기록도 상태를 구분해 확인할 수 있도록 설계한다.
- 목록은 metadata를 읽어 만들고, 목록 조회 때 모든 CSV를 로딩하지 않는다. 별도 DB는 초기에는 필요하지 않다. 색인을 추가하더라도 원본 metadata에서 재구성 가능하게 한다.
- 사용자가 실험을 선택하면 해당 runId로 기록 상세 화면을 연다. 브라우저가 임의 CSV 경로를 전달하지 않는다.
- 과거 기록 조회는 활성 실험과 독립된 API/조회 문맥으로 구성한다. 현재 /api/history의 활성 runId 제한을 그대로 재사용하지 않는다.

## 7. 과거 기록 분석 화면

- 상세분석의 그래프·단위 변환·추종 오차 계산·붉은 이상 구간·하단 상태 이력 바를 공용 구성으로 재사용한다.
- 완료된 실험을 열면 **전체**를 기본 선택해 실험 시작부터 종료까지 보여준다.
- 60초 / 5분 / 10분 / 30분 / 1시간 / 전체 선택을 재사용한다. 유한 범위는 우선 그 기록의 마지막 측정 시각을 기준으로 하며, 전체 구간 확대를 통해 과거 부분을 확인한다.
- 기록 화면은 실시간 스트림을 붙이지 않는다. 다른 실험이 실행 중이어도 그 값이 과거 그래프에 추가되면 안 된다.
- 과거 실험의 config와 metadata를 사용한다. 현재 실행 설정으로 과거의 단위/한계값을 해석하지 않는다.
- 당시 기록한 판정 결과를 그대로 표시한다. 현재 알고리즘으로 다시 판정하는 기능은 별도 과제다.
- runId는 서버 재시작 후에도 변하지 않는다. 현재 서버 세션 ID로 과거 프레임을 거부하지 않도록 실시간 상태와 기록 조회 상태를 분리한다.

## 8. 구현 순서

1. 설정 저장 형식과 검증, 실행별 폴더/metadata 규격을 정한다.
2. 공통 실험 관리자와 상태/API를 만든다. 기존 상태 계약에 종료 대기를 반영한다.
3. main.py 시작 시 MOCK 자동 실행을 없애고 시작 명령에 따라 생성/기록하도록 변경한다.
4. MOCK에서 설정한 모델/ID·왕복 시간·가속 시간·대기 시간·횟수를 반영하고 왕복 완료 후 종료를 검증한다.
5. 제어 페이지와 개요 시작/종료 버튼을 같은 상태/API에 연결한다.
6. 기존 dashboard/experiment 왕복 실행과 종료 예약을 관리자에 연동한다. 원본 실험 코드는 유지한다.
7. 같은 개발 범위에서 날짜별 로그 목록과 과거 실험 분석 화면을 구현한다.
8. 설정 저장 → 시작 → 왕복 완료 후 종료 → 로그 목록 반영 → 기록 선택 → 전체 구간 분석을 끝까지 검증한다.

## 9. 완료 기준

- 서버만 켜거나 설정을 저장해도 실험/CSV 기록이 시작되지 않는다.
- 저장 설정과 실행별 설정 사본이 일치하고, 설정한 왕복 횟수·타이밍이 MOCK 동작에 반영된다.
- 종료 요청 후 현재 왕복과 대기 구간의 기록이 계속되며 다음 왕복은 시작하지 않는다.
- 종료 경로에서 torque OFF 명령을 보내지 않는다. 정상 종료 설정은 false로 고정한다.
- 반복 클릭/복수 브라우저 요청에도 실행은 하나이며, 늦은 종료 요청은 다른 runId에 적용되지 않는다.
- 재시작한 실험의 ID/CSV/0초 기준이 새로 만들어지고 이전 기록은 유지된다.
- MOCK/실제 기록이 분리되고 날짜별 폴더에 실행 당시 설정·원본·요약이 함께 남는다.
- 날짜 경계 통과, 오류/강제 종료, 서버 재시작 시에도 기록을 정상 완료로 오인하지 않는다.
- 로그 화면은 저장된 기록으로 상세분석과 같은 값을 재현하고 활성 실험의 실시간 데이터를 섞지 않는다.
- 서버와 브라우저를 재시작한 후에도 완료된 실험이 목록에 나타나고 같은 기록을 다시 열 수 있다.
