# 상세분석 기록 조회 및 MOCK CSV

> 현재 제어·날짜별 저장·로그 사용법은 [CONTROL.md](CONTROL.md)를 참고한다. 서버는 대기 상태로 시작하고 실험 시작 요청 이후 수집/저장한다.

상세분석 범위: 60초(기본), 5분, 10분, 30분, 1시간, 전체.
유한 범위는 최신 측정 시각을 기준으로 잘라낸 원본 구간이며, 전체는 현재 실험 시작부터 누적한다. 샘플링이나 평균을 적용하지 않는다. 개요 및 실시간 전송 버퍼는 계속 최근 60초다.

## 실행과 저장

`main.py`는 대기 상태로 시작한다. 제어에서 설정 저장 후 실험 시작을 누르면 0초부터 MOCK 기록이 시작하며, 브라우저 연결 여부와 무관하게 계속된다. 종료 요청은 현재 왕복을 마무리한 뒤 반영한다. 테스트만 `mock_prehistory_ms`로 합성 이력을 명시할 수 있다.

저장 위치는 `src/dashboard/runtime/mock_runs/YYYY/MM/DD/<시각>_<runId>/`이며 config.toml, metadata.json, telemetry.csv를 기록한다. 실행마다 새 ID/폴더를 만들고 이전 파일을 보존한다. 실제 제어 실험은 별도 experiment_runs 루트를 사용한다. 로그 페이지에서 종료된 과거 실행을 조회할 수 있다.

CSV 한 행은 전송한 하나의 측정 프레임이다. 식별자, 순번, 시각, 모터 정보와 `registers`, `diagnosis` 열을 저장한다. 뒤의 두 열은 JSON 문자열로 53개 주소의 원시값·상태·측정 시각과 판정 결과를 손실 없이 보존한다. 원시 레지스터를 표시 단위로 바꾸거나 추종 오차를 계산하는 역할은 프론트엔드에 유지된다.

완전한 CSV 행을 기록하고 flush한 뒤 같은 프레임을 WebSocket에 발행한다. 이 flush는 읽기 가시성을 위한 것으로 정전까지 견디는 fsync 보장은 아니다. 저장에 실패하면 새 측정값 전송을 중단하고 오류 상태를 전달한다. 정상 서버 종료 시 파일을 닫고 종료 시각/상태를 기록한다. 프로세스 강제 종료 시 남은 running 기록은 다음 시작 때 실행 주체를 확인해 복구한다.

## 조회 계약

`GET /api/history?source=mock&runId=<id>&sourceSessionId=<generation>&durationSec=300&motorId=1&model=XM430-W210`

- source: mock 또는 csv. CSV 모드는 기존 안내 파일이 지정한 현재 실험을 읽기만 한다.
- durationSec: 60, 300, 600, 1800, 3600, 0. 0은 전체.
- runId, sourceSessionId: 필수. 현재 실험/파일 세대가 달라지면 409.
- motorId, model: 선택 필터.
- afterSeq: 선택적인 순번 하한(기본 0).
- 임의 파일 경로를 요청할 수 없다.

응답은 schemaVersion=1, runId, serverSessionId, sourceSessionId, throughSeq, latestElapsedMs, samples를 포함한다. samples는 기존 WebSocket 원본 프레임과 같은 구조다. throughSeq는 응답이 읽은 완결된 기록의 마지막 순번이다. 현재 구현은 한 요청에 해당 구간 원본 전체를 반환하며 페이지 분할·다운샘플링을 하지 않는다. 조회와 JSON 직렬화는 작업 스레드에서 실행한다. 지원하는 클라이언트에는 gzip으로 손실 없이 압축 전송하며 측정값이나 샘플 수를 줄이지 않는다.

## 프론트엔드 연결

- 60초는 기존 motorStore를 사용한다.
- 더 긴 범위는 useAnalysisHistory가 CSV 조회를 시작한다. 조회 중 수신한 새 측정 배치를 별도로 보관한다.
- HTTP 응답과 실시간 배치를 세션/실험/모터로 확인하고 순번으로 중복 제거한다. 새 프레임을 누락시키지 않도록 실시간 버퍼가 잘라내기 전 배치를 구독한다.
- 기록을 그래프용 값으로 한 번 변환해 보관한다. 모든 측정 시점은 유지하되, 장기 이력에 53개 주소 객체를 중복 보관하지 않는다.
- 범위 변경 또는 소스/실험 변경 시 이전 요청을 취소하고 늦게 도착한 응답은 무시한다. 재연결 snapshot 수신 시 선택 범위의 CSV 기록을 다시 불러온다.
- 0.1초마다 화면에 반영한다. 유한 구간은 시간으로 제거하며 전체는 계속 누적한다. 실제 갱신 속도는 기록량과 PC 성능에 따라 느려질 수 있다.
- Ctrl+휠로 과거 구간을 확대하면 화면 표시를 일시정지한다. 데이터 수신/기록은 계속되며 화면 재개 버튼으로 최신 상태를 표시한다.
- 하단 상태 이력은 정상/이상을 색으로 표시한다. 미수신 또는 판정 없는 시점은 정상으로 꾸미지 않고 회색/빈 구간으로 남긴다.

## 검증 범위와 한계

자동 검증은 CSV↔전송 값 일치, 1시간 36,001개 원본 조회, 범위별 보관, 요청 중 수신 병합, 실험 격리, 소스 전환 취소, 저장 실패, 새로고침 복원을 포함한다. 실제 모터는 구동하지 않는다.

전체 범위는 시간에 비례해 메모리가 증가한다. 기록 조회 시 해당 CSV를 스캔하므로 아주 긴 실험은 읽기·전송·렌더링에 시간이 필요하다. 과거 실행 검색, 자동 CSV 정리, DB 인덱스, 장시간 다운샘플링은 이번 구현에 포함하지 않는다.

## 로그의 기록 조회

/api/runs/{runId}/history는 종료된 실험 전용이다. 로그 선택 시 전체를 기본으로 읽으며 useRecordedRun이 당시 metadata로 변환한다. 실시간 구독과 합치지 않는다. 다른 실행의 시작/종료 및 현재 서버 세션 변경은 기록 그래프에 영향을 주지 않는다.
